- PNG-рендер новых BPMN и измененных диаграмм НЕ проверен визуально с читаемым результатом - в песочнице агента нет кириллического шрифта (эффект воспроизведен и на уже существующем `Use-Case.puml`, то есть проблема окружения, а не файлов). - Ссылки между новыми `.md`-файлами не проверялись автоматическим линтером (инструмента для этого в проекте нет) - проверены вручную при написании.

**Ключевые решения, принятые пользователем**:

1. Ключевые сценарии - Create Trip / Add Expense / Settlement (SC-001..003), совпадают с существующими sequence-диаграммами.
2. Auth-расхождение (Google в документации vs email в коде) фиксируется по факту: документация приведена в соответствие с кодом (email-вход), Google OAuth не выдается за реализованное поведение.
3. Заморожены как не подлежащие пересмотру: схема БД и алгоритм расчета долгов. Схема аутентификации - открыта для пересмотра (см. ADR-001).
4. TelegramBot исключен из архитектурных материалов (C4, Use Case) - вне текущего фокуса (веб).
5. NFR зафиксированы как целевые (не измеренные) ориентиры: NFR-PERF-001 (p95 < 300 мс при ~10 RPS), NFR-REL-001 (availability ≥ 99% + 0 потерь данных), NFR-SEC-001 (100% trip-scoped действий требуют членства в поездке + HttpOnly/CSRF).
6. ADR-001: раздельная авторизация - email для Web UI, token-based (JWT) для будущего REST API.
7. ADR-002: хранение изображений чеков остается в S3/MinIO (без изменений).
8. ADR-003: целевое состояние доставки - единый `docker-compose` (Postgres + MinIO + Web UI); реализация - отдельная задача.
9. Документы структурированы по смыслу (`docs/`, `img/`), а не по лабораторным - отдельного README для лабы нет, все ссылки - в корневом `README.md`.

**Отклоненные альтернативы**:

- ADR-001: полноценный Google OAuth вместо email-входа - отклонено как существенная работа вне текущего объема, требующая внешнего провайдера и секретов.
- ADR-002: BLOB в Postgres и локальная файловая система - отклонены из-за конфликта с NFR-PERF-001 и с планами на горизонтальное масштабирование.
- ADR-003: переход на Kubernetes - отклонено как избыточное для текущего масштаба проекта.
- Удаление старого `b_process.drawio` - отклонено в пользу сохранения его как обзорной схемы.

**Зафиксированные, но не исправленные пробелы** (код не менялся):

- `TripsController.Details` не проверяет членство пользователя в поездке (расхождение с целевым NFR-SEC-001).
- Атомарность операции "запись в БД + загрузка файла в S3" в `ReceiptImageService` не проверена.
- PostgreSQL и Web UI не контейнеризованы (только MinIO в `docker-compose.yml`) - целевое состояние зафиксировано в ADR-003, реализация - отдельная задача.
